# KHDEMLI marketplace server

## التشغيل محلياً

يتطلب Node.js 22.13 أو أحدث.

```powershell
npm.cmd install
npm.cmd start
```

افتح العنوان الذي يظهر في الطرفية، افتراضياً `http://127.0.0.1:3000`. لا تفتح `index.html` مباشرةً عبر `file://`، لأن تسجيل الدخول والخدمات والمحادثات تعمل عبر الخادم.

## النشر على InfinityFree

استضافة InfinityFree لا تشغّل خادم Node.js؛ لذلك تستخدم هذه النسخة واجهة PHP مع MySQL عند رفعها هناك. المحادثات تُحدّث تلقائياً كل خمس ثوانٍ بدلاً من Socket.IO. ارفع إلى مجلد `htdocs` فقط `index.html` و`.htaccess` ومجلد `api` بعد إعداد `api/config.php`. لا ترفع `server.js` أو `node_modules` أو ملفات قاعدة SQLite أو ملفات تصدير الترحيل إلى المجلد العام.

1. نزّل نسخة احتياطية من `data/khdemli.sqlite` الحالي من مدير الملفات، واحتفظ بها خارج `htdocs`.
2. أنشئ قاعدة MySQL في لوحة InfinityFree، ثم استورد `api/schema.sql` من phpMyAdmin.
3. انسخ `api/config.example.php` إلى `api/config.php`، وضع بيانات اتصال MySQL كما تظهر في اللوحة، وكلمة مرور إدارة قوية لا تقل عن 16 حرفاً، وسراً عشوائياً لا يقل عن 32 حرفاً. يمكن توليد السر من PowerShell باستخدام:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

4. للحفاظ على الحسابات والخدمات والمحادثات والتقييمات، شغّل محلياً على ملف SQLite الذي نزّلته:

   ```powershell
   node scripts\export-sqlite-to-mysql.js "C:\path\to\khdemli.sqlite" "C:\path\to\mysql-migration.sql" "C:\path\to\account-reset-codes.csv"
   ```

   استورد ملف SQL الناتج إلى قاعدة MySQL بعد `schema.sql`. يحتوي CSV على رمز خاص بكل حساب قديم؛ وزّع كل رمز على صاحبه بطريقة خاصة وآمنة. يحتاج أصحاب الحسابات القديمة إلى إدخال الرمز من «نسيت كلمة المرور؟» لإعداد كلمة مرور جديدة. الرموز صالحة 30 يوماً، وملفات التصدير تحتوي بيانات شخصية وبيانات اعتماد مجزأة؛ لا ترفعها إلى `htdocs` أو Git واحذفها بأمان بعد إتمام النقل والتوزيع.
5. ارفع `index.html` و`.htaccess` ومجلد `api` إلى `htdocs`، وأنشئ `api/config.php` هناك. اترك ملفات PHP تُنفّذ من الاستضافة، ولا تنشر ملف التصدير أو قاعدة SQLite.

فعّل شهادة HTTPS من لوحة الاستضافة قبل تسجيل الدخول، ثم يجب أن يعيد `https://اسم-موقعك/api/bootstrap` JSON، لا صفحة HTML. ملف `.htaccess` يمنع الوصول العام إلى مجلدات `data` و`node_modules` وملفات إعداد PHP. لا تحذف نسخة SQLite القديمة حتى تتأكد من اكتمال نقل البيانات واختبار تسجيل الدخول والخدمات والمحادثات.

## البيانات

تُخزّن الحسابات والخدمات والمحادثات في `data/khdemli.sqlite`، وتُنشأ الجداول تلقائياً عند أول تشغيل. كلمات المرور مشتقة بـ scrypt مع ملح عشوائي، وتُخزّن الجلسة في ملف ارتباط HttpOnly. تُحفظ ملفات قاعدة البيانات محلياً ولا تُضمّن في Git.

يستخدم الجميع حساباً واحداً لإضافة الخدمات ومراسلة أصحابها عبر محادثة خاصة داخل الموقع. من صفحة أي خدمة يمكن فتح صفحة تجمع خدمات صاحبها. يمكن لصاحب الخدمة حذف خدمته، ويؤدي ذلك إلى حذف المحادثات المرتبطة بها. الرسائل تصل لحظياً للمشاركين المتصلين.

يمكن تقييم مقدم الخدمة في ملفه الشخصي بعد تبادل الرسائل بين الطرفين في محادثة على المنصة. التقييم والكتابة موجهان للشخص، لا لإعلان خدمة بعينه، ويسمح بتقييم واحد لكل حساب مع إمكانية تعديله لاحقاً.

## غرفة الإدارة

على InfinityFree، اضبط كلمة مرور المشرف في `api/config.php`. بقية تعليمات هذا القسم تخص تشغيل خادم Node.js محلياً أو على استضافة تدعمه.

افتح `/aa` من أي رابط للموقع للدخول إلى لوحة إدارة الخدمات والمحادثات. الوضع المعتاد يتطلب كلمة مرور سرية بطول 16 حرفاً على الأقل. للتجربة المحلية فقط، يمكن تفعيل كلمة مرور قصيرة مثل `07` بشرط بقاء الخادم على `127.0.0.1` وخارج وضع الإنتاج:

```powershell
$env:HOST = "127.0.0.1"
$env:ADMIN_PASSWORD = "07"
$env:ADMIN_ALLOW_WEAK_PASSWORD = "1"
npm.cmd start
```

هذا الخيار يُرفض تلقائياً في وضع الإنتاج أو إذا رُبط الخادم بعنوان غير محلي. لا تستخدمه على شبكة أو موقع منشور؛ بعد التجربة أوقفه واستخدم كلمة مرور قوية. لا تضع كلمة المرور في ملفات الموقع أو Git. جلسة الإدارة منفصلة عن حسابات المستخدمين، وتُلغى عند إعادة تشغيل الخادم. لا تُعرض نصوص المحادثات إلا بعد فتح محادثة محددة من اللوحة، ويسجل النظام عمليات قراءة المحادثات وحذف الخدمات في `admin_audit_log`. أخبر المستخدمين في سياسة الخصوصية بأن المشرف قد يراجع المحادثات عند الحاجة للإشراف؛ يوضح الموقع ذلك في صفحة الخصوصية وداخل غرفة المحادثة.

يعمل الخادم محلياً افتراضياً. لاستخدامه على أجهزة أخرى، عيّن `HOST=0.0.0.0` واسمح بالمنفذ في جدار الحماية. لا تعرض الخادم للإنترنت قبل وضعه خلف HTTPS وتفعيل `NODE_ENV=production`.

على Windows يمكن ضبط المتغيرات قبل التشغيل في PowerShell:

```powershell
$env:HOST = "0.0.0.0"
$env:NODE_ENV = "production"
npm.cmd start
```

عند استخدام وكيل عكسي HTTPS واحد، اضبطه لتمرير `X-Forwarded-Proto`، ثم عيّن `TRUST_PROXY=1` كي يتعرف Express على HTTPS. خذ نسخاً احتياطية من مجلد `data` بشكل آمن؛ حذفه يمسح الحسابات والخدمات نهائياً.

### النشر على `https://khdemli.xo.je/`

هذه التعليمات تخص نشر خادم Node.js على استضافة تدعمه، ولا تنطبق على نطاق InfinityFree المجاني `*.wuaze.com`.

وجّه سجل DNS للنطاق إلى منصة الاستضافة، وفعّل شهادة HTTPS من المنصة أو الوكيل العكسي. اضبط `NODE_ENV=production` و`TRUST_PROXY=1` و`ADMIN_PASSWORD` قوية في إعدادات الاستضافة؛ يستمع الخادم تلقائياً على `0.0.0.0` في وضع الإنتاج، ويستخدم المنفذ الموجود في `PORT` إن وفرته المنصة. يجب أن يمرر الوكيل العكسي ترويسة `Host` الأصلية و`X-Forwarded-Proto: https` إلى الخادم. بذلك تعمل الجلسات وواجهات الموقع على النطاق نفسه عبر HTTPS.

لا تفتح الموقع عبر HTTP ولا تغيّر إعدادات ملفات الارتباط الآمنة أو فحص مصدر الطلبات؛ يجب أن يكون الموقع والـAPI على النطاق نفسه. إذا كانت المنصة لا تستخدم وكيلاً عكسياً واحداً، فلا تفعّل `TRUST_PROXY=1` قبل ضبط عدد الوكلاء الموثوقين بما يناسب بنيتها.
